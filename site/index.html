From first direction to trusted product memory Taste workflow
01 / INTERVIEW◎

Ask what matters

A greenfield landing page needs a focus. The agent asks what should lead.

“Show the workflow in action.”
02 / EXPLORE↗

Try a direction

The host builds a first version. Your reaction guides the next pass; the Pack stays untouched.

working draft · held in the host’s task
03 / CONTINUE→

Keep the host moving

When you like the direction, Taste nudges the host to finish the product’s own build and review workflow.

user likes direction ≠ Pack approval
04 / VERIFY✓

Approve the tested version

The host runs its relevant checks and asks you to approve that exact version and the reusable Decision.

host-owned · checks, review, and push timing
05 / PROMOTE⌁

Record only what held up

At the configured checkpoint, the host gives Taste the approved artifact and its validation evidence. Shipped evidence makes it Conformance.

Expression → Conformance only after accepted, validated, shipped evidence
Your first reaction guides the work. It does not write to the Pack.

The useful kind of memory

Judgment that compounds with the product.

Taste gives your coding harness a practical way to carry decisions forward, while leaving the product’s direction in your hands.

01

It lives with the product

The Pack is versioned in the product repository, so its context can travel with the code and stay reviewable.

02

Conversation guides the work

Early reactions and corrections help the host iterate. They stay out of the Pack until the tested version and Decision are approved.

03

Evidence earns reuse

Conformance requires an accepted Decision, matching validation and approval evidence, inspected shipped work, and no unresolved gap.

04

Your harness stays in charge

Taste provides focused Skills and tools. Your coding agent owns the loop, implementation, and judgment.
