# Conformance applies current product guidance

Conformance describes the task approach of applying established, sourced product guidance. It is not a folder or persistent mode. Route by the user's task and affected surface, then load relevant Pack guidance.

1. Check for `taste/`. If absent, continue from repository evidence without starting a product-wide sweep. A correction that resolves into a clear reusable lesson can create a minimal Pack for the affected surface through `taste-expression`. If present, inspect it; if `setupStatus` is `in_progress`, do not present starter text as product guidance. For `usable_partial`, load guidance only for listed supported coverage; otherwise load only relevant Skills and references.
2. Resolve the user's request mode and surface, then load only canonical references relevant to that pair. Use repository sources for component APIs, design-system rules, accessibility, and interaction contracts instead of duplicating them in the Pack.
3. For non-trivial UI work — layout, interaction, flow, or visual structure, rather than a typo or mechanical token swap — write a short task-local brief before editing product files. The brief states the intent, the Pack constraints that apply, and the options you are rejecting. Unresolved alternatives stay in that brief, not in the Pack. Then implement or review within the user's scope. Shipped UI is evidence, not automatic proof every pattern is intentional. Separate observed patterns from explicit product constraints and preserve uncertainty. If the user gives a correction that conflicts with an existing reference, apply the current direction and revise the relevant guidance—or create a minimal Pack for this surface—after the check-and-repair comparison below when the lesson is reusable. Preserve evidence and explain the judgment when that helps a future assistant; do not add rationale or rejection sections just to fill a template.
4. Check and repair when you change UI. Run the product's existing checks and the relevant Pack checklist before the edit and again after it. Keep the change only if the checker shows improvement or no regression; otherwise revert and retry. Taste does not run these checks or own a CI gate. When session tracing is on, follow `taste-design` and record `checkSummaries.before` and `checkSummaries.after` on `taste_session_record`.
5. Use the harness's source, browser, computer-use, and rendered-preview tools when the task needs visual or interaction evidence. Report the pages and states you actually viewed.
6. When the user rejects a direction, corrects the result, or disagrees with a design choice, revise the work and run the same check-and-repair comparison. If the feedback expresses a reusable lesson, update the scoped guidance or create a minimal Pack for that surface through `taste-expression`, preserving its evidence and rationale where useful. No product-wide sweep, separate promotion workflow, or additional approval is required. Report guidance updates and remaining evidence gaps.

Conformance is a host approach label for applying established guidance, not a status to persist or derive for each task.
