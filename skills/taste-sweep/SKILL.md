# Sweep shipped UI into product Skills and checklists

The host gathers, reconciles, and self-checks evidence, then writes product-specific Skills, references, and checklists into the Pack. Structured Decision files are legacy and are not part of the routine sweep learning loop.

1. Check whether `taste/` exists. If present, call `taste_pack_inspect` and `taste_part_state` with `taskIntent: inspect_only` before work. If absent, do not initialize an empty Pack before discovery. Use repo routes, navigation, source, and product docs to inventory the whole user-facing product, including distinct surfaces and their main flows. Record the inventory and coverage status in the host task.
2. Inspect all reachable user-facing surfaces with the host's browser or computer-use tools. Follow primary flows and relevant alternates; inspect states the product can enter, including empty, loading, error, permission, and success states where applicable. Capture screenshots and record URL/page, flow step, date, viewport, state, and what each capture supports. If the product is too large for one pass, split bounded surfaces across host-supported tasks, Claude tasks, or cloud agents. Give workers the same evidence template and prohibit Pack writes; the host reconciles their findings and owns final judgments.
3. Correlate rendered evidence with source, Git history, reviews, design files, and canonical product sources. Separate verified facts, observed patterns, inferences, and open questions. Do not infer that a repeated pattern is intentional from repetition alone. Report inaccessible surfaces and other coverage gaps. Never claim a screen was seen if it was not. Do not store private production data without authorization.
4. Consolidate an evidence-backed surface map and useful checklist items. Each item should state a concrete check, scope, source, rationale, exception, and confidence. Separate directly observed behavior from inferred intent; treat shipped patterns as useful evidence but not proof of universal policy. Include a coverage list and gaps.
5. The host agent reviews its own sweep and draft for coverage, source traceability, factual accuracy, consistency, and actionable guidance. No separate developer or human review/approval stage is required. Initialize a Pack if absent, then derive its structure from the product sweep. Choose only the guidance categories and metadata that solve recurring needs across the inspected surfaces; do not populate a fixed reference catalog or create empty files. Update `manifest.json` with the surface inventory. Write one concise entry Skill that resolves task mode first and routes by surface to the product-specific references and checklists. Group related routes into meaningful surfaces and create durable references or checklists only when evidence shows they will help future work, rather than one file per URL. Include shared product facts, source authority, or coverage metadata only when they capture useful information not already clear from the canonical product sources and surface map. Keep the entry Skill as a single front door, link to canonical component/design-system/accessibility sources instead of duplicating them, and prevent audits from turning into edits or copy work from expanding into redesign. Add shipped exemplars only when there is useful evidence; add a Gate only for a reliably mechanical rule and eval material only when repeatable evidence exists. Do not create `AGENTS.md`, tooling scripts, or empty example files just to match another repository's tree. Do not leave generic scaffold text as product-specific guidance. A minimal Pack with a concise router and a few precise surface checklists is better than a large, generic reference library. Use `taste_pack_write` for these references and checklists; `taste_record_signal` remains a legacy structured Decision path. The host self-review is the quality check. Taste does not decide which product checks apply or run them.
6. In later design conversations, treat the user's corrections, rejections, and disagreements as direct evidence. Apply the feedback in the active task, then add or revise the reusable checklist item with `taste_pack_write` after self-checking the change. Do not ask for a separate Pack review or Decision approval. Validate the Pack and call `taste_part_state` with `taskIntent: inspect_only`; summarize surfaces, sources and states actually reviewed, checklist guidance written, and remaining evidence gaps.

Legacy structured Decision activity is still derived from its stored evidence. Checklist guidance applies independently to each scoped task even when no structured Decision exists. Other parts retain their existing derived state.
